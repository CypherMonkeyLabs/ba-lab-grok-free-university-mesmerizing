SQL, measures, and process mining for business analysts.

  • A measure needs a question, a formula, a source, and an owner. HEART, from the cited Google Research paper, is a set of user-centered categories, not a benchmark. SQL, as the PostgreSQL tutorial introduces it, filters and groups rows. Process mining reconstructs paths from event logs you are allowed to use. Leave unknown numbers blank.
  • Question: are same-day callbacks happening? Formula: abnormal results called the same calendar day, divided by abnormal results received that day. Source: the call log plus the lab file. Owner: the nurse lead. Act when the rate drops under the line the clinic sets.
  • This lab does not invent the line. The clinic does.
  • SQL for a question. PostgreSQL's tutorial introduces SQL as the way to ask a database a question. Learn SELECT, filter, join, and group. You do not need to be the database administrator. You do need to know whether the column you were promised actually exists.
  • Spreadsheets. A spreadsheet is often the current system. Before you replace it, learn its formulas, its hidden columns, and who repairs it on Fridays. This note is practice advice. A specific product manual is not cited because none was required for the habit.
  • Conceptual, logical, physical. A conceptual model uses business words. A logical model adds keys and cardinality. A physical model adds types and indexes for one database. Do not start at the physical model with stakeholders who came to talk about orders.
  • KPI definition sheet. For each indicator write the question it answers, the formula, the grain, the source system, the refresh, the owner, and the threshold for action. HEART, from the Google Research paper on user-centered metrics, is one way to group product measures: happiness, engagement, adoption, retention, and task success.
  • HEART. The paper 'Measuring the User Experience on a Large Scale: User-Centered Metrics for Web Applications' is the public source for the HEART categories. Use the categories as a checklist. Do not invent a benchmark number this lab did not measure.
  • Measures and OKRs. A key result that counts tasks completed is usually an output. Prefer a result a customer or the operation can feel. Tie the measure back to the need in the business case.
  • Power BI, as a study topic. Microsoft Learn has a page titled What is Power BI. On 16 October 2026 the readable body asked for authorization, so this lab does not describe product features from it. Lucky's notes do not claim Power BI experience.
  • Tableau, not linked. Tableau is a visual analytics product teams use for dashboards. Its public page did not open in the 16 October 2026 check, so it is not linked and no feature is described. This lab does not claim Tableau experience for Lucky.
  • Process mining. The IEEE Task Force on Process Mining site opened. Process mining uses event logs to reconstruct how work actually flowed. It is evidence about the current state. It still needs a person to decide whether the flow is acceptable.
  • Dashboards. A dashboard is a decision surface. Lead with the question, then the number, then the breakdown. If a chart does not change a decision, leave it off. Cite the definition of every figure.
